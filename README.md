專案名稱：PROJECT_NAME

簡介
- 輕量級全端樣板，用於快速啟動小型服務或原型。
- MVP 目標：提供健康檢查端點、最小首頁、以及可擴充的資料庫與文件骨架。

系統需求
- Node.js >= 18
- 套件管理器：pnpm 或 npm
-（可選）PostgreSQL 14+（若使用資料庫）

快速啟動（本地）
1) 取得原始碼並進入專案資料夾。
2) 安裝依賴：
   - 使用 pnpm：pnpm install
   - 或使用 npm：npm install
3) 設定環境變數：建立 .env 並填入必要鍵（見下方「環境變數」）。
4) 啟動開發伺服器：
   - pnpm dev
   - 或 npm run dev
5) 瀏覽器開啟本機服務（預設埠請依環境變數 PORT）。
6) （如專案提供）可在 /api/health 測試健康檢查。
7) 建置與啟動正式模式：
   - pnpm build && pnpm start
   - 或 npm run build && npm start

部署概述（雲端或自管主機）
- 準備執行環境：Node.js >= 18，並設定必要環境變數。
- 建置產物：於 CI/CD 或伺服器上執行建置指令。
- 啟動服務：以系統服務或程序管理工具常駐（依環境而定）。
-（若使用資料庫）套用資料庫 schema／遷移後再對外服務。
- 設定反向代理與 TLS（視需求）。

環境變數（鍵名示意）
- APP_ENV：執行環境（如 development/production）
- PORT：服務監聽埠
- APP_BASE_URL：服務對外基底網址（供組合連結用）
- DATABASE_URL：資料庫連線字串（若使用資料庫）
- AUTH_SECRET：用於簽章／加密的祕密字串（請妥善保護）

資料夾說明（建議結構，可依需求調整）
- web/：前端與 API 路由（Next.js 專案根）
- api/：API 規格或相關資源（例如 OpenAPI 定義）
- db/：資料庫 schema、遷移與政策設定
- docs/：部署與架構說明文件

常見問題
- 啟動失敗且顯示埠已被占用：修改 PORT。
- Node 版本不符：升級至 Node.js >= 18。
- 相依套件安裝失敗：清除快取並重試（pnpm store prune / npm cache clean --force），或切換網路環境。

安全與隱私
- 切勿將祕密與金鑰提交至版本控制。
- 使用只讀或最小權限的資料庫帳號於生產環境。
